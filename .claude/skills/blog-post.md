# Blog Post Skill

Generate a fully optimized blog post for Veloxa and deploy it to GitHub. Follow every step — no shortcuts.

## Trigger

User says "write a blog post", "create a blog post", "new blog post", "blog post about [topic]", or invokes `/blog-post`.

---

## Phase 1: Research & Preparation

### 1.1 Pick a primary keyword

- Read `Keywords.csv` for the full keyword list with search volumes and competition.
- Read `used-keywords.md` to see which primary keywords are already taken.
- Pick a primary keyword that is **NOT** in used-keywords.md.
- Favor keywords with higher search volume and "Low" competition.
- Pick 4-5 secondary keywords from the CSV (or invent closely related ones if the CSV doesn't have enough). These form the keyword cluster.

### 1.2 Load the reference files

Read every file in `src/Reference/`:

| File | Purpose |
|------|---------|
| `voice.md` | How Veloxa writes — sentence rhythm, word choices, banned words, formatting rules |
| `humour.md` | Humor rules — dad jokes, self-deprecation, parenthetical asides, sign-off |
| `opinions.md` | Strong industry takes — deploy one per post, backed by numbers |
| `stats.md` | Real numbers — use exact figures, never round them |
| `stories.md` | Recurring anecdotes — adapt one per post, never invent new ones |
| `on-page-seo.md` | The 80+ item checklist — every post must satisfy every applicable item |

### 1.3 Understand the blog data structure

Read `src/data/blogPosts.ts` and `src/pages/BlogPost.tsx` to understand:
- The `BlogPostData` interface fields
- How content is rendered (markdown-like syntax: `**bold**`, `## H2`, `### H3`, `* bullet`, `1. ordered`, `![alt](url)`)
- What schema/SEO tags are auto-generated by the BlogPost component

## Phase 2: SERP Analysis

### 2.1 Search Google for the primary keyword

Use WebSearch to search the primary keyword. Note the "People Also Ask" questions for the FAQ section.

### 2.2 Fetch and analyze the top 3 ranking pages

For each of the top 3 organic results, use WebFetch with this prompt:

> Analyze this page in detail: 1) What is the format (listicle, guide, tutorial, comparison)? 2) Estimate the word count. 3) List every H2 heading. 4) What topics does it cover? 5) Does it have a table of contents, FAQ section, featured snippet answer? 6) What's the page title?

### 2.3 Extract the SERP pattern

Create a comparison table:

| | Page 1 | Page 2 | Page 3 |
|---|---|---|---|
| Format | | | |
| Words | | | |
| TOC? | | | |
| FAQ? | | | |
| Common topics (all 3) | | | |
| Topics 1-2 missed | | | |

**Rules:**
- **Format:** Match the dominant format (2 of 3 = the format to use)
- **Length:** Target the average word count of the 3 pages, within 20%
- **Topics:** Cover every topic ALL 3 pages include
- **Extra topics:** Add 1-2 topics NONE of them covered well

## Phase 3: Write the Blog Post

### 3.1 Plan the structure

Before writing, plan:

1. **Title** — 50-60 chars, primary keyword near the start
2. **Slug** — primary keyword, hyphens, lowercase, under 60 chars (e.g. `digital-marketing-services`)
3. **Meta description** — 150-160 chars, keyword + benefit + soft CTA
4. **Hero image** — from Unsplash or Pexels, relevant to the topic
5. **H2 outline** — the full section structure
6. **Internal links** — 3-5 links to Veloxa service pages or other blog posts
7. **External links** — 2-3 links to authoritative sources (.gov, .edu, major industry)
8. **FAQ questions** — 6-8 questions from "People Also Ask"

### 3.2 Writing rules (from voice.md)

- **Short sentences.** Mostly under 18 words.
- **One idea per sentence.** If "and" appears twice, split it.
- **Answer first, then context.** Never the other way around.
- **Deadpan delivery.** No exclamation marks. No emojis.
- **Real numbers over adjectives.** Not "very fast" — say "under 60 minutes."
- **Use "I" for blog posts** (the author is speaking personally).
- **Banned words:** unlock, leverage, empower, synergy, seamless, cutting-edge, world-class, best-in-class, comprehensive solution, "in today's fast-paced world", "we pride ourselves on", "contact us" (say "call us" or "give us a call"), "reach out", "utilize", "affordable", "competitive pricing", "quality service".

### 3.3 Humor rules (from humour.md)

- Every 300-500 words needs one moment: a dad joke, a self-deprecating aside, or a pop-culture drop.
- A 3,000-word post targets: 3-5 dad jokes/puns, 2-3 self-referential asides, 1-2 parenthetical dips, 1 sign-off that lands.
- Punch at yourself/the industry — never at the reader.

### 3.4 Opinions (from opinions.md)

- One strong opinion per post, backed by a number or a story.
- Tell people when NOT to hire/buy — this is the single biggest voice tell.
- "90% of agencies miss X" lands harder than "X is important."

### 3.5 Stats & stories (from stats.md, stories.md)

- Use exact numbers from stats.md where relevant.
- Adapt one story from stories.md if it fits. Never invent a new one.
- If no story fits, skip the story rather than making one up.

### 3.6 Content structure template

```
**Featured snippet answer** — direct answer + primary keyword in first 100 words.
1-2 paragraphs expanding the answer.

![Hero or section image](url)

## H2: Core topic 1 (with secondary keyword)
### H3: Subtopic
Content with bullet points, bold key phrases, short paragraphs.

![Section image](url)

## H2: Core topic 2 (with secondary keyword)
...

## H2: Strong opinion section
One strong take, backed by a number or story.

## H2: Frequently Asked Questions
### FAQ question 1?
2-4 sentence direct answer.
### FAQ question 2?
...
(6-8 questions total)

## The Sign-Off
A closing line that makes the reader smile. Not "we're here to help 24/7!" Something human.
```

### 3.7 Image rules

- Find relevant images from Pexels or Unsplash.
- Use the direct image URL format: `https://images.pexels.com/photos/...?auto=compress&cs=tinysrgb&w=1200`
- Place images above H2 sections (not after).
- Every image needs descriptive alt text with the keyword where natural.
- The hero image goes in the `image` field of BlogPostData.

## Phase 4: SEO Optimization

### 4.1 Apply every applicable item from on-page-seo.md

Before finalizing, verify:

**Head & Metadata:**
- [ ] Title tag: 50-60 chars, primary keyword near start
- [ ] Meta description: 150-160 chars, keyword + benefit + soft CTA
- [ ] OG/Twitter Card handled by BlogPost.tsx

**URL:**
- [ ] Slug: short, hyphens, lowercase, keyword present, under 60 chars

**Headings:**
- [ ] Exactly one H1 (the title), contains primary keyword
- [ ] H2 to H3 hierarchy (never skip levels)
- [ ] H2s use secondary keywords + questions
- [ ] No keyword stuffing

**Copy:**
- [ ] Primary keyword in first 100 words
- [ ] Direct answer in first paragraph
- [ ] Length within 20% of SERP top-3 average
- [ ] Short paragraphs (1-4 sentences)
- [ ] 8th-10th grade readability
- [ ] Active voice
- [ ] Bold key phrases (sparingly)
- [ ] Bullets and numbered lists

**FAQ:**
- [ ] 6-8 questions from "People Also Ask"
- [ ] 2-4 sentence direct answers
- [ ] FAQ schema auto-generated by BlogPost.tsx

**Images:**
- [ ] Alt text on every image
- [ ] Descriptive filenames (hyphens, not underscores)
- [ ] Featured/hero image set

**Links:**
- [ ] 3-5 internal links with descriptive anchor text
- [ ] 2-3 external links to authoritative sources
- [ ] Contextually placed in body copy

**E-E-A-T:**
- [ ] Author byline (handled by BlogPost.tsx)
- [ ] Published date displayed
- [ ] Real stories, numbers, opinions from reference files
- [ ] Cited authoritative sources

**Long-form (1500+ words):**
- [ ] Table of contents auto-generated by BlogPost.tsx (>3 H2s)
- [ ] Back-to-top button auto-handled by BlogPost.tsx

## Phase 5: Add to Codebase & Deploy

### 5.1 Add the post to blogPosts.ts

Insert the new `BlogPostData` object as the **first entry** in the `blogPosts` array in `src/data/blogPosts.ts`.

```typescript
{
    slug: 'your-slug-here',
    image: 'https://images.pexels.com/photos/...',
    category: 'Marketing',
    title: 'Your Title Here',
    excerpt: 'Your 150-160 char meta description here.',
    date: 'Month DD, YYYY',
    readTime: 'X min read',
    featured: true,
    content: `
**Featured snippet answer with primary keyword in bold.**

Rest of content with proper markdown formatting...
    `
}
```

**Content formatting rules:**
- Use backticks for the `content` field (template literal)
- Inside content: `**bold**`, `## H2`, `### H3`, `* bullet`, `1. ordered`, `![alt](url)`
- Paragraphs separated by blank lines
- Watch for unescaped single quotes in the title string — use smart/curly apostrophes instead of straight ones

### 5.2 Update used-keywords.md

Add the primary keyword to the table:

```markdown
| primary keyword | Full Blog Post Title | slug | Month DD, YYYY |
```

### 5.3 Verify

Run the TypeScript compiler to catch errors:

```bash
npx tsc -b --noEmit
```

Fix any compilation errors (common: unescaped quotes in title string).

### 5.4 Deploy to GitHub

```bash
git add src/data/blogPosts.ts used-keywords.md
git commit -m "feat: new blog post - [Title]"
git push origin master
```

Vercel auto-deploys on push to master.

## Quality Gates (do not skip)

Before shipping, read the post aloud. Does it:

- [ ] Sound like a human wrote it (not AI, not a brochure, not LinkedIn)?
- [ ] Answer the main question immediately?
- [ ] Include at least one strong, numbered opinion?
- [ ] Have a moment of humor every 300-500 words?
- [ ] Tell the reader when NOT to buy/hire?
- [ ] End with a sign-off that makes the reader smile?
- [ ] Pass every applicable item in the on-page SEO checklist?

If any box is unchecked, revise before shipping.
